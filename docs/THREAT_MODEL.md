# Threat model

## Why not a plain deterministic contract, and why not a centralized LLM/operator

A deterministic contract cannot decide whether a delivered API or AI-agent task output *semantically* satisfies a natural-language acceptance criterion — that requires reading evidence and applying judgment, which is exactly the class of decision GenLayer's validator-consensus model exists to make safely reproducible. A single centralized LLM or human operator is not acceptable either: it is a single point of failure/collusion with no independent check, and SpecLock's entire purpose is to make that judgment independently reproduced and compared by validators (`gl.vm.run_nondet_unsafe` with a custom validator function — see `docs/CONSENSUS.md`), not asserted once and trusted.

## Evidence trust

- **Who controls each source:** API evidence URLs point at the provider-controlled service being evaluated; agent evidence URLs point at provider-controlled or buyer-controlled artifact hosts. Neither party is trusted — every criterion's judgment function independently re-fetches/re-derives rather than trusting the leader's claimed observation (see `docs/CONSENSUS.md`).
- **Stability / snapshot:** `submit_evidence` records a submitter-declared `content_digest` and a URL; `request_evaluation` freezes all submitted-but-not-yet-frozen evidence and computes `_evidence_snapshot_commitment` (a hash over frozen receipt ids + digests) before invoking evaluation, so the evidence set judged is fixed and auditable even though the remote content itself can still change or vanish afterward (a live URL is not content-addressed storage).
- **When a claim must stay UNVERIFIABLE:** any criterion with no matching evidence, or whose independent re-observation fails to reach validator agreement, derives `UNVERIFIABLE`/`INSUFFICIENT` rather than silently defaulting to PASS or FAIL (`_probe_api_criterion`, `_judge_agent_criterion`).

## Threats and how SpecLock addresses or defers them

| Threat | Handling |
|---|---|
| Malicious buyer/provider (false accusation, refusal to acknowledge, fake success) | Only parties to the specific agreement can call its write methods (`_is_party`); overall verdict is derived from independently-judged per-criterion findings, not either party's say-so. |
| Fabricated endpoints / misleading HTTP 200 | `_probe_api_criterion` distinguishes `reachable` from `functional` and never treats a bare 200 as delivery; functional check requires a parseable JSON body. |
| Endpoint drift / mutable response / stale snapshot | Each validator re-fetches at evaluation time; `evidence_snapshot_commitment` records what evidence set was judged, but the module docstring and `docs/GENLAYER_CAPABILITIES.md` are explicit that a live HTTP resource cannot be guaranteed replayable later (capability 38 honesty requirement). |
| URL/SSRF tricks (localhost, private ranges, embedded credentials, non-HTTPS) | `_validate_url` rejects non-`https` schemes, embedded userinfo, and a blocklist of loopback/private host patterns (`127.`, `10.`, `192.168.`, `169.254.`, `localhost`, `::1`). This is a contract-level best-effort check, not a substitute for GenVM's own egress policy, which this environment could not independently verify (`docs/GENLAYER_CAPABILITIES.md`). |
| Prompt injection inside web pages / agent traces | The agent-profile judge prompt explicitly instructs the model to treat quoted evidence as untrusted data, never instructions (`_judge_agent_criterion`). This is a mitigation, not a proof — LLM prompt-injection resistance cannot be verified deterministically, which is exactly why the validator reruns the judgment independently rather than trusting a single leader pass. |
| Forged attestations / self-reported tool logs | The agent profile's docstring and tests (`test_speclock_agent.py::test_agent_missing_artifact_without_independent_evidence_is_unverifiable`) make unresolved/self-only evidence `UNVERIFIABLE`, not `PASS`. |
| Adversarial leader output / forged "PASS" | `validator_fn` in both `_probe_api_criterion` and `_judge_agent_criterion` independently re-derives the decision-critical fields and rejects any leader result failing `isinstance(leaders_res, gl.vm.Return)` or field disagreement. **Not exercised under real multi-validator consensus in this environment** — Direct Mode only runs the leader path (see `docs/GENLAYER_CAPABILITIES.md`); this is a documented gap, not a verified proof. |
| Validators seeing different evidence / consensus non-finality / equivocation | Evidence is frozen (status `FROZEN`) before evaluation begins, and `evidence_snapshot_commitment` is recorded; true cross-validator agreement was not observed from this environment (no live consensus run). |
| Replay / double settlement | `settle()` requires `agreement.settlement_id == ""`; `recover_inconclusive()` requires phase `RECOVERY_PENDING` (a settle() side effect), so neither can fire twice on the same agreement. Covered by `test_settlement_conservation_on_pass`'s explicit double-settle-rejected assertion. |
| Unauthorized refunds / arbitrary payout amounts | All settlement amounts are computed deterministically from the finalized evaluation's `overall_finding`/`findings`, never from the nondeterministic judgment text itself (Section 5 "core pattern": nondet answers *what the evidence shows*, deterministic code answers *what that authorizes*). |
| Appeal spam / replay | `max_appeal_rounds` bounds appeal rounds per agreement (default `MAX_APPEAL_ROUNDS = 2`); a resolved appeal's `resolution` moves out of `FILED_UNADJUDICATED` so it cannot be re-resolved; `test_appeal_replay_after_resolution_rejected` exercises the round cap. |
| DoS via huge inputs / unbounded histories / duplicate IDs | `MAX_CRITERIA`, `MAX_SPEC_CHARS`, `MAX_CRITERION_CHARS`, `MAX_EVIDENCE_URL_CHARS`, `MAX_EVIDENCE_METADATA_CHARS`, `MAX_EVIDENCE_PER_AGREEMENT`, `MAX_APPEAL_GROUNDS_CHARS`, `MAX_FETCH_BYTES`, `PAGE_SIZE_MAX`, and duplicate-criterion-id rejection in `_compile_criteria` are all enforced and tested (`test_speclock_security.py`). |
| Sybil reputation / duplicate-count gaming | Reputation only updates in `finalize_verdict` (post-appeal-window, once per agreement's single finalize call), never on a provisional verdict; `test_reputation_only_updates_on_finalized_outcome` asserts this. |
| Privacy leaks | No credentials or off-chain secrets are accepted or stored; evidence URLs are rejected if they embed userinfo. Full evidence content is not stored on-chain (only digest+URL+metadata), per the brief's privacy requirement — but see the caveat below. |
| Griefing the shared logical clock (advancing `now` prematurely to close someone else's appeal window) | **Known, accepted limitation.** Any party calling any time-gated method can advance the contract-wide clock (bounded by `MAX_CLOCK_ADVANCE_SECONDS`), which could close another agreement's appeal window early if that party is also party to this one's timing. This is the direct cost of there being no verified on-chain time source (see `docs/GENLAYER_CAPABILITIES.md`); it is not hidden behind a false claim of a trusted oracle. |

## Confidentiality caveat

A content digest alone proves commitment, not that validators could independently inspect the underlying content, and SpecLock does not claim otherwise: evidence URLs must be publicly fetchable `https` resources for the evaluators to functionally re-derive anything (unreachable/private evidence resolves to `UNVERIFIABLE`/`INSUFFICIENT`, never silently trusted).
