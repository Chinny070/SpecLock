## Deadline / time-source conclusion (re-audited)

GenLayer's documented web-access and equivalence-principle pages were consulted conceptually, but the determining facts here are empirical: the installed runner's `gl.message` struct carries no timestamp, and the lower-level `message_raw['datetime']` field that does exist in the SDK cannot be verified to refresh correctly across calls in this installed Direct Mode harness version (its wiring is dead code — see the capability row above). An earlier revision of this contract used a caller-supplied `now` parameter checked against a monotonic logical clock; a follow-up security audit showed this was manipulable by a self-interested party in either direction (claim an early `now` to keep contesting, or a late one to force the counterparty's window closed) and rejected it. **SpecLock now uses no asserted time source of any kind.** Deadline-shaped behavior is reproduced through mutual two-party consent gates (`finalize_verdict`, `cancel_or_expire`) and an always-available, round-capped appeal path (`file_appeal`), none of which depend on any party's claim about what time it is. See `docs/THREAT_MODEL.md` "clock redesign" and `DECISION.md` item 1 for the full reasoning and the regression tests that prove a lone party cannot force finalization or expiry.
