## 2. Native escrow (capability #3) — root cause fixed; redeploy corrected

A first `@gl.public.write.payable` `fund_agreement` plus `emit_transfer`-based payouts in `_settle`/`resolve_appeal` were implemented, deployed (`0xaa54c150B128843e5638cF31e2F1B632117ccBE2`), and tested against a funded signer. Deposits genuinely worked; payouts to a plain wallet (EOA) recipient failed on-chain (`result_name:"NO_MAJORITY"`, `value_credited:false`, decoded `"Contract ... not found"`).

The root cause was then found: `gl.get_contract_at(...)` addresses another GenLayer intelligent contract, not a general value-transfer primitive — the wrong tool for paying a plain wallet. The fix, `gl.evm.contract_interface` (`_EthAccount` in `contracts/speclock.py`), was found via a sibling project (AgentCourt) that solved the identical problem on the identical runner/network with real live proof. `fund_agreement`/`file_appeal` are payable again; `_settle`/`resolve_appeal` credit a pull-payment `claimable` balance; `withdraw()` pays it out. 52/52 Direct Mode tests pass.

Two attempts to redeploy `contracts/speclock.py` and live-verify this fix (`0xd60dfaC9B3473Fce6bC97CD47F7a5Ac80c97A74e`, `0x192CA2229677E4e1d0d115d4665E2634Bf0A25d1`) both failed at the constructor-call level: both deploy transactions reached `FINALIZED` consensus but with `execution_result: "ERROR"` and a decoded stderr traceback `TypeError: SpecLock.__init__() takes 1 positional argument but 2 were given`. Root cause, confirmed by comparing raw deploy calldata byte-for-byte against the working deployment: the deploy command `genlayer deploy --contract contracts/speclock.py --args '[]'` passed the CLI's variadic `--args` flag a single shell token `[]`, which the CLI treated as one literal string constructor argument rather than an empty array — not a platform or contract issue, a deploy-command mistake. Corrected by omitting `--args` entirely (`genlayer deploy --contract contracts/speclock.py`), matching AgentCourt's own documented working invocation. See `docs/DEPLOYMENT.md` for the corrected redeploy and live verification results.

## How to reproduce or extend the lifecycle tests already run

See `docs/DEPLOYMENT.md` "How real on-chain lifecycle execution was achieved" for the full method: `npm install genlayer-js` in a scratch directory, generate a fresh disposable buyer/provider pair with `createAccount()` per agreement, fund both from a wallet you control via `genlayer account send`, then run the full `create_agreement → accept_agreement → fund_agreement → freeze_agreement → submit_evidence → request_evaluation → finalize_verdict ×2 → settle` sequence in one script process (`createAccount()` never exposes a raw private key, so a generated account cannot be reused across separate process invocations — this is what stranded agreement `"3"` on an earlier deployment).
